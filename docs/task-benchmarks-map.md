# Карта задач и бенчмарков LLM: «какая модель справится достаточно и дешевле»

Снимок ссылок: **2026-10-04, таксономия v2** (углублена по решению владельца: классы →
подклассы; добавлен разбор реальных конвейеров владельца). Все ссылки проверены в этот
день (см. «Обновление»). Назначение: ответ на вопрос «у меня есть задача - какая модель
справится лучше за меньшее время и деньги», включая вариант «локальной достаточно».

## Как отвечать на вопрос (методика)

1. **Определить домен → класс → подкласс задачи** по таксономии ниже.
2. Взять **топ-3-5 кандидатов из профильного лидерборда подкласса** (не из общего
   «интеллект-рейтинга»); 1 дорогой фронтендер = судья качества, остальные - дешёвые.
3. Собрать **мини-eval на СВОИХ 20-50 реальных задачах** подкласса (образец -
   `evals/exam-suite-v2/`: задачи не из открытых датасетов, эталон, анти-контаминация).
   Чужие бенчмарки дают шорт-лист; «достаточно» доказывается только своими задачами.
4. Посчитать **цену за решённую задачу**: облако - цена токенов (OpenRouter API,
   скрипт ниже); локальная - GPU-секунды (свои замеры, таблица ниже).
5. Порог «достаточно» фиксируется заказчиком ДО прогона (иначе выбор подгоняется).

## Что вообще решают LLM (якоря таксономии)

- [HF Tasks](https://huggingface.co/tasks) - канонический список задач машинного обучения:
  NLP (генерация текста, суммаризация, QA, перевод, классификация), мультимодальность,
  аудио (ASR/TTS), зрение, табличные задачи.
- [Anthropic Economic Index](https://www.anthropic.com/economic-index) - срез РЕАЛЬНОГО
  использования: на что тратят LLM в работе (программирование, письмо, анализ, образование,
  поиск). Полезно как чек-лист «чего я ещё не автоматизировал».

## Таксономия v2: домены → подклассы

Формат строки: подкласс → чем мерить. Пометка «свой eval» = живого канонического
бенчмарка нет, меряется только на своих задачах (как собрать - в методике выше).

### Домен A. Письменная работа (тексты)

| Подкласс | Примеры | Чем мерить |
|---|---|---|
| Деловая переписка | письма партнёрам, еженедельные отчёты | свой eval: корпус одобренных писем + сверка формул/фактов |
| Резюме и сопроводительные (HR-тексты) | rewriting резюме, письма под вакансию | канонического бенчмарка НЕТ (исследуется только employer-side скрининг); свой eval: сверка с корпусом отправленных, факт-ревизия, формат «было→станет» |
| Стилизация под канон (style transfer) | запрет нейрослопа, тон бренда | свой eval: словарь запретов + реджект-паттерны |
| Редактура/корректура | правки чужого текста без потерь | свой eval: дифф-дисциплина (не трогать лишнее) |
| Креатив (проза, сценарии, роль) | художественные тексты | [EQ-Bench](https://eqbench.com) (creative writing), категория [LMArena](https://lmarena.ai) |
| Перевод | RU↔EN, техперевод | [FLORES-200](https://github.com/facebookresearch/flores) |
| Суммаризация | конспекты статей/лекций/встреч | [HELMET](https://github.com/princeton-nlp/HELMET) (summarization-сьют) + свой контроль потерь смысла |
| Факт-точность длинных текстов | нет выдуманных дат/цифр/цитат | [Vectara Hallucination Leaderboard](https://github.com/vectara/hallucination-leaderboard) (ежемесячно обновляемый рейтинг галлюцинаций), [FActScore](https://github.com/shmsw25/FActScore) (атомарные факты) |

### Домен B. Код

| Подкласс | Примеры | Чем мерить |
|---|---|---|
| Автодополнение (FIM) | middle-infill в редакторе | канонического живого лидерборда нет; свой FIM-бенч (прецедент 1C) + LiveCodeBench completion |
| Код по описанию | функции/алгоритмы из условия | [LiveCodeBench](https://livecodebench.github.io), [BigCodeBench](https://github.com/bigcode-project/bigcodebench) |
| Агентная разработка (SWE) | issue в реальном репо, multi-file | [SWE-bench](https://www.swebench.com) (Verified/Lite/Multilingual/Multimodal) |
| Редактирование в проекте | точечные правки по инструкции | [Aider polyglot](https://aider.chat/docs/leaderboards/) |
| Терминал/ops-агент | shell, деплой, окружение | [Terminal-Bench](https://github.com/laude-institute/terminal-bench) |
| Тест-генерация | юнит-тесты с покрытием | BigCodeBench частично + свой eval (покрытие и ловля регрессий) |
| Ревью кода | найти баг/дыру до мерджа | свой eval (прецеденты: инвертированные колонки эвал-отчёта, пропущенный P0) |
| Объяснение/миграция кода | «что делает», порт на другой язык | свой eval (эталонные переводы с прогоном тестов) |

## Реальные конвейеры владельца → подклассы (где модели ломаются)

Разбор двух примеров владельца от 2026-10-04 + остальных постоянных конвейеров:

### Резюме, сопроводительные, поиск работы (домены A, D, F)

Ломающиеся способности и чем ловить:
1. **Дрейф инструкций** (добавляют «хвосты»-интерпретации, меняют одобренные формулы) →
   IFEval-класс + свой словарь-канон: сверка с корпусом отправленных писем обязательна.
2. **Выдумывание фактов** (даты, цифры, «реконструкция из битого дампа как цитата») →
   факт-точность (Vectara/FActScore-класс) + жёсткое правило: цифры только из первички.
3. **Пропуски в хронологических цепочках** (карьерная цепочка без этапа = логический разрыв) →
   только свой eval: чек-лист полной цепочки перед сборкой.
4. **Нейрослоп и кальки** → свой словарь запретов; при сомнении - обязательное независимое
   ревью вторым агентом.
Вывод: канонического бенчмарка на этот класс нет - твой корпус+ревизия и есть бенчмарк.

### Обработка статей/лекций (KB-пайплайн) (домены A, C, E, G)

1. **Галлюцинации в сводках** → Vectara-рейтинг как шорт-лист + свой контроль: каждое
   утверждение конспекта находимо в источнике.
2. **Слабый структурированный вывод** (ломанный YAML/JSON фронтматтер) → JSONSchemaBench
   + свой валидатор-гейт (прецедент: аудит claims).
3. **Классификация в таксономию** (tech/pm/ai-домены) → свой eval на размеченных примерах.
4. **Длинные транскрипты** → HELMET/LongBench v2 как фильтр кандидатов, свой контроль потерь.

### Coding-агенты (домен B) - свой exec-бенчмарк + SWE-bench шорт-лист.

### Мониторинг вакансий (домены C, F): извлечение полей + классификация + GUI/API-агенты -
свой eval на реальных карточках (прецедент hh-фильтров).

## Внешние бенчмарки на сервере: локальный прогон (проверено 2026-10-04)

Клоны: `/data/home/<user>/proj/external-benchmarks/` (вне репо): MMLU-Pro,
google-research (IFEval), LiveCodeBench, gorilla (BFCL). Цепочка «локальная
модель → официальный бенчмарк → официальные метрики» проверена вживую
(gemma4-26B base на GPU2): MMLU-Pro **работает** (форк evaluate_from_apiX:
`--url http://127.0.0.1:8033/v1`; патчи: API_KEY из env, лимит `MMLUPRO_LIMIT`
на категорию; инкрементальный мердж результатов в eval_results/), IFEval
**работает** (генератор наш `scripts/run_ifeval_api.py` + родной скоринг;
gemma4-26B: strict/loose 0.880 на 50 промптах). LCB и BFCL склонированы, для
прогона нужны HF-датасет и зависимости (см.
`experiments/external-benchmarks-smoke-2026-10-04/README.md`). Лаунчер:
`external-benchmarks/run-mmlupro-local.sh`.

## Живые мета-источники (кто где сейчас)

- [Artificial Analysis - методология](https://artificialanalysis.ai/methodology): Intelligence
  Index, **Cost per Task**, Output Speed (ток/с), TTFT, blended price (7:2:1). Главный источник
  «интеллект vs цена vs скорость»; отдельные индексы для кодинг-агентов, кибербезопасности, речи.
- [LMArena](https://lmarena.ai): слепые человеческие сравнения (Elo) по категориям.
- [LiveBench](https://livebench.ai): контаминационно-стойкий сьют (вопросы обновляются).
- [OpenRouter Rankings](https://openrouter.ai/rankings): реальные объёмы использования (браузером;
  API из датацентров 403).
- [Vectara Hallucination Leaderboard](https://github.com/vectara/hallucination-leaderboard):
  ежемесячный рейтинг галлюцинаций при суммаризации.
- [llm-stats.com](https://llm-stats.com): агрегатор счётов.
- [Open LLM Leaderboard (HF)](https://huggingface.co/spaces/open-llm-leaderboard/open_llm_leaderboard):
  **архив** - только исторические снимки.
- Scale SEAL - браузером (403 для curl из датацентров).

## Цена и скорость: обновляемые данные

- **Облачные:** OpenRouter API `GET https://openrouter.ai/api/v1/models` (ключ не нужен).
  **Запускать с asrock/ПК1** (датацентровые IP ловят 403 - проверено 2026-10-04).
  Скрипт: `scripts/bench-map-refresh.sh` → `benchmarks-map/openrouter-<дата>.tsv`.
- **Локальные:** скорость только на своём железе. Замеры стенда (V100 32GB, GPU2,
  llama.cpp server-cuda, Q4_K_M, fast mode, temp 0.6):

| Модель | VRAM весов | Скорость decode | Контекст |
|---|---|---|---|
| Gemma-4-26B-A4B (MoE, 4B активных) uncensored/base | 16.8 GB | 86.6 / 83.2 ток/с | 64k |
| Gemma-4-31B (dense) uncensored/base | 18.7 GB | 28.1 / 28.6 ток/с | 32k |

  Цена локального токена = (GPU кВт × тариф × сек/токен); 31B на V100 ≈ 100k ток/час.
  Локальная выгодна: большой постоянный трафик, офлайн, приватность.
- VRAM-математика: Q4_K_M ≈ 0.57 ГБ/млрд параметров (+1-3 ГБ KV на 32k при q8); правило:
  weights + KV + ~1 ГБ буферы ≤ VRAM минус чужие процессы.
- **Бесплатный тир:** в снапшоте 2026-10-04 у OpenRouter 22 модели с $0, среди них
  `google/gemma-4-26b-a4b-it:free` и `google/gemma-4-31b-it:free` (ctx 256-512k) - те же
  модели, что проверены локально; можно пробить «достаточно ли» бесплатно до скачивания весов.
